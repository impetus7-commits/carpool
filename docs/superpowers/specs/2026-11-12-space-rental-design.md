# 학교 공간 대여 웹앱 설계서

작성일: 2026-11-12 · 위치: `space-rental/` (기존 카풀 코드는 건드리지 않음)

## 목적
교직원과 학생이 학교 공간을 살펴보고(사진·영상·수용 인원·용도·시설·특이사항) 건물 → 층 → 교실 순서로 눌러 사용을 신청한다. 관리자는 모든 쓰기 기록을 본다.

## 확정된 결정
| 항목 | 결정 |
|---|---|
| 기술 | 구글시트에 묶인 앱스크립트 웹앱 한 개 |
| 계정 | 학교 Workspace 계정. 배포는 "실행: 나, 액세스: 도메인 내 사용자" |
| 신청 자격 | `사용자` 탭에 등록된 이메일만. 미등록 계정은 조회만 |
| 승인 | 교직원·관리자는 즉시 확정, 학생은 승인 대기 → 관리자 승인·반려 |
| 시간 단위 | 교시 (`교시` 탭에서 이름·시각 수정) |
| 층 화면 | 시트의 건물·층·순서로 자동으로 그리는 약식 배치도 |
| 반복 예약 | 시작일~종료일 사이 고른 요일마다 같은 교시로 신청. 겹치는 날은 목록을 보여 주고 빼고 신청할지 묻는다 |
| 추천 | 외부 AI 없이 빈 시간·인원·용도·시설·검색어로 점수를 매기고 이유를 문장으로 제시 |

## 시트 탭
- `공간`: ID, 건물, 층, 순서, 이름, 수용인원, 용도, 시설, 특이사항, 소개, 사진, 영상, 신청가능
- `사용자`: 이메일, 이름, 역할(교직원·학생·관리자), 소속
- `교시`: ID, 이름, 시작, 종료
- `예약`: ID, 묶음ID, 공간ID, 날짜, 교시, 이메일, 이름, 역할, 소속, 목적, 인원, 상태, 신청일시, 수정일시, 처리자, 비고
- `기록`: 일시, 이메일, 이름, 동작, 예약ID, 공간, 날짜, 내용, 변경전, 변경후
- `설정`: 항목, 값, 설명 (학교이름, 안내문, 예약가능일수, 반복예약최대일수)

예약 1건 = 공간 1곳 + 날짜 1일 + 교시 여러 개. 반복 예약은 날짜마다 1건씩 만들고 같은 `묶음ID`를 준다.
상태는 확정·승인대기·반려·취소. 삭제는 행을 지우지 않고 `취소`로 바꾼다.

## 규칙
- 같은 공간·날짜에 교시가 겹치는 확정·승인대기 예약이 있으면 신청 불가. 모든 쓰기는 스크립트 잠금 안에서 처리.
- 지난 날짜, 예약가능일수를 넘는 날짜, 정원을 넘는 인원은 신청 불가.
- 수정·취소는 본인과 관리자만. 학생이 교시를 바꾸면 다시 승인 대기.
- 반복 예약 취소는 "이 날만" 또는 "이 날부터 남은 일정 모두".
- 모든 쓰기(신청·수정·취소·승인·반려)는 `기록` 탭에 변경 전후와 함께 남는다. 웹 화면에는 기록을 고치는 기능이 없다.

## 구조
| 파일 | 역할 |
|---|---|
| `Logic.gs` | 순수 계산: 날짜, 겹침 판단, 반복 날짜 펼치기, 추천 점수 |
| `Code.gs` | 웹앱 API: 권한 확인, 검증, 예약 쓰기, 기록 |
| `Store.gs` | 시트 읽기·쓰기, 로그인 이메일, 잠금, 시각 |
| `Setup.gs` | 탭 머리글, 예시 데이터, 처음 설정 메뉴 |
| `index.html` | 화면 전체 (공간·추천·내 예약·관리) |
| `dev/` | 미리보기와 테스트용 가짜 저장소 (`Store.gs` 대신 끼움) |

`Code.gs`는 `Store.gs`의 함수만 통해 데이터를 만진다. 그래서 테스트와 미리보기는 `Store.gs`만 가짜로 바꾸고 실제 서버 코드를 그대로 돌린다.

## 검증
- `node --test`로 겹침·반복·추천 계산과 API 흐름(권한, 승인, 충돌, 기록) 확인
- `preview.html`을 휴대폰·컴퓨터 크기로 열어 화면 확인
- 실제 구글 배포는 학교 계정에서만 가능하므로 `설치방법.md`에 따라 사용자가 직접 수행
